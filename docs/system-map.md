# 项目全景：Agent 所在的业务系统

MAX 和分析管道依托一个完整 CRM 领域。此页按用户任务归类，避免将原项目中的每个目录误称为一个独立服务。

| 业务区域 | 主要责任 | 与 MAX / 分析的连接 |
| --- | --- | --- |
| 账号与权限 | 身份、角色、会话、客户归属 | 每次读取与执行都使用服务端身份和当前作用域 |
| 客户档案 | 基本资料、标签、备注、人工成交与交付 | 形成分析输入与助手客户上下文 |
| WhatsApp 对话 | 入站、发信、回执、媒体、翻译 | 提供可回查原文及异步分析触发 |
| 导入与媒体 | 聊天导入、媒体处理、进度、错误恢复 | 处理材料覆盖与来源一致性 |
| AI 客户分析 | 分块分析、观察、综合评估和发布 | 把材料转成可复核结构化结果 |
| 规则与评分 | 显式事实、评分事件、当前等级与阈值 | 为优先级与经营统计提供业务口径 |
| 跟进与销售活动 | 联系安排、任务、活动统计 | 连接建议和用户确认后的行动 |
| 管理与洞察 | 仪表盘、团队统计、风险与重要提醒 | 提供受角色约束的聚合工具 |
| MAX Agent | 问答、业务检索、上下文、文件与受控草稿 | 编排工具、形成可引用的回答 |
| NEWS | 外部信息、报告和业务影响提示 | 作为独立信息入口，不等于客户原始事实 |
| 数据与任务基础 | PostgreSQL、Prisma、pg-boss、共享 schema | 提供一致性、持久状态和异步恢复基础 |

## 一条端到端业务路线

消息入站 → 验签与身份核实 → 持久化客户和消息 → 任务触发分析 → 结构与来源校验 → 发布当前评估 → 销售查看优先级 → MAX 按具体问题读取资料和原文 → 用户确认跟进行动。

这是一条理解系统的典型路线，不表示每次入站同步执行全部步骤；任务、能力开关、当前模式和权限会影响实际执行。
